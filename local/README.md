# Локальний хаб

Python-половина проєкту: той самий трекер, але з **Telegram-ботом** і
**підказками Claude** — тим, чого не може статична сторінка на GitHub Pages.

Головна, встановлювана версія лежить у корені репозиторію
([README](../README.md)). Ця тека потрібна, тільки якщо хочеш:

- кидати фото їжі просто в Telegram і тегувати їх кнопками під повідомленням;
- отримувати нагадування про відбій, навіть коли застосунок закритий;
- щоб тег «солодке / звичайне» підказував Claude по фото.

Дані тут свої — SQLite у `data/` — і з веб-версією наживо не синхронізуються.
Перенести їх можна копією: кнопка **«Копія для телефона»** в налаштуваннях
дашборда (або `GET /api/backup`) віддає JSON у форматі веб-версії, а та читає
його через «Відновити з копії».

## Що вміє

**Задачі.** Одноразові й повторювані — щодня або в конкретні дні тижня
(«зал» тільки Пн/Ср/Пт). Щоденна відмітка, лічильник streak на кожну
повторювану задачу, теплокарта за 12 тижнів і список виконаного по датах.

**Сон.** Дві кнопки — «ліг спати» і «прокинувся», час підставляється сам,
тривалість рахується автоматично. Оцінка якості 1–5 зірками. Графік по
днях або по тижнях із лінією норми. Помічник нагадує, коли час лягати, і
попереджає, якщо останні ночі стабільно коротші за норму.

**Їжа.** Фото приходять через Telegram-бота, під кожним одразу дві кнопки —
«Солодке» / «Звичайне». Лічильник днів без солодкого, статистика по тижнях
і галерея-стрічка, що гортається по датах. Якщо є ключ Anthropic, тег
підказує Claude, а користувач лише підтверджує.

**Огляд.** Одна сторінка згори: активні стріки, сон за тиждень, стрік без
солодкого і мініатюри останніх фото.

## Запуск

Найпростіше — подвійний клік на `start.bat`. Він сам створить `.venv`,
поставить залежності, зробить `.env` з прикладу і відкриє дашборд.

Руками:

```bash
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m hub
```

Дашборд буде на <http://127.0.0.1:8765>. Telegram-бот піднімається в тому
самому процесі, якщо в `.env` є токен. Усі команди виконуються з теки `local/`.

Корисні прапорці:

```bash
python -m hub --open        # ще й відкрити браузер
python -m hub --no-bot      # тільки дашборд
python -m hub --bot-only    # тільки бот, без веба
python -m hub --port 9000   # інший порт
```

## Telegram-бот

1. У [@BotFather](https://t.me/BotFather) створити бота, отримати токен.
2. Вписати його в `.env` як `TELEGRAM_TOKEN`.
3. Запустити хаб і написати боту `/start` — він запам'ятає, кому слати
   нагадування.

Бот особистий: писати йому може або той, хто перший сказав `/start`, або
ті, чиї числові id перелічені в `TELEGRAM_ALLOWED_IDS`. Решту він ігнорує.

Команди: `/start`, `/sleep` (кнопки «ліг спати» / «прокинувся»),
`/streak` (усі стріки одним повідомленням), `/today` (план на сьогодні).
Фото можна слати без жодної команди — просто надіслати знімок.

Нагадування бот перевіряє раз на п'ять хвилин і читає налаштування щоразу,
тому змінений у дашборді час відбою діє одразу, без перезапуску.

Якщо бота ще нема — модуль «Їжа» не простоює: на його вкладці є кнопка
«Додати фото з комп'ютера».

## Підказка тегу через Claude (необов'язково)

Етап 2 модуля «Їжа». Якщо в `.env` є `ANTHROPIC_API_KEY`, бот перед
питанням про тег показує фото моделі й підписує, що на ньому схоже на
солодке. Кнопка з підказаним тегом позначається галочкою — залишається
натиснути або виправити. Вимикається через `HUB_VISION=0`; модель
задається `HUB_VISION_MODEL` (типово `claude-opus-5`).

Підказка ніколи не ставить тег сама і не ламає збереження фото: якщо запит
не вдався, бот просто питає як завжди.

## Де що лежить

```
local/hub/      бекенд
  config.py     читання .env, шляхи, значення за замовчуванням
  db.py         з'єднання з SQLite, налаштування, хелпери дат
  schema.sql    таблиці
  tasks.py      модуль 1: задачі, стріки, теплокарта
  sleep.py      модуль 2: ночі, графіки, помічник
  food.py       модуль 3: фото, теги, стрік без солодкого
  vision.py     необов'язкова підказка тегу через Claude
  web.py        FastAPI: JSON-API + статика
  bot.py        Telegram-бот і нагадування
  __main__.py   веб і бот в одному циклі подій
local/static/   дашборд: index.html, styles.css, app.js
local/tools/selftest.py  перевірка логіки на тимчасовій базі
local/data/     база й фото (у git не потрапляє)
```

Логіка тут і в `store.js` веб-версії однакова: копія, знята з цього хабу, дає
в застосунку ті самі стріки й графіки.

Графіки намальовані власним SVG замість Chart.js — так дашборд працює без
інтернету і бере кольори з теми.

## Дані

```
tasks       (id, name, recurrence_rule, note, active, sort_order, created_at)
task_logs   (id, task_id, date, completed)
sleep_logs  (id, date, sleep_time, wake_time, duration, quality, note)
food_logs   (id, timestamp, date, photo_path, tag, note, source,
             suggested_tag, suggestion_note)
settings    (key, value)
```

`recurrence_rule` — це `once`, `daily` або `days:1,3,5` (1 = понеділок).
`sleep_logs.date` — це «ніч на», тобто дата, коли лягав: якщо ліг о 01:20,
запис усе одно належить попередній ночі. Тривалість зберігається в хвилинах.

Модулі не знають один про одного — спільні в них тільки база й дашборд.
Резервна копія — це просто копія теки `data/`.

### Як рахуються стріки

**Задачі:** скільки *планових* днів поспіль виконано, рахуючи назад від
сьогодні. Невиконаний сьогоднішній день стрік не рве — він ще попереду.
Дні, коли задача не стоїть у плані (субота для «залу»), пропускаються, а не
рвуть лічильник.

**Без солодкого:** скільки днів поспіль немає жодного фото з тегом
«Солодке». День без записів вважається чистим — лічильник про те, чи було
солодке, а не про те, чи ти фотографував.

## Перевірка після змін

```bash
.venv\Scripts\python tools\selftest.py
```

Проганяє логіку всіх трьох модулів на тимчасовій базі — теку `data/` не
чіпає. Друкує рядок на кожну перевірку і повертає ненульовий код, якщо
щось розійшлось.

## Налаштування в дашборді

Шестерня у шапці: норма сну, час відбою, час ранкового нагадування і
скільки останніх ночей дивиться помічник. Усе інше — у `.env`.
